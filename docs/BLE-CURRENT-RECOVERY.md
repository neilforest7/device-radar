## 限定恢复方法

当前公开 `BluetoothUpdateDeviceRecord` 固定选择 Classic PHY，不能用于已验证的纯 BLE 修复。本轮对匹配本机二进制的内部入口另行复核：`0x411030` 输入必须恰好 `0x72A` 字节，PHY 为 `1`、更新标志仅 `0x20`、别名为空；输出为空且返回字节数必须为 `0`。

这个分支清空运行时别名，保留已有磁盘 `00`。它没有直接保存磁盘或发送本次 LE 名称更新通知，因此后续 PnP 与正常重连仍需独立验收。内部引用、锁和忙状态位也会变化，不能把它描述为有公开支持保证的属性 setter。

GET 与 UPDATE 使用相同的地址查找函数和 LE 选择；GET 返回一条记录不证明内部候选只有一个。两次调用之间没有原子身份令牌，仍有短时状态变化的限制。

本机脚本默认只做 Preflight，实际已编译并成功读取预期运行时测试名，`updateAttempted=false`。写入模式额外执行：

1. 固定本轮不可变快照、原始 v3 恢复点、机器、系统 build/修订号/启动时间和五份模块散列；核对实例、容器、HID 型号、设备状态与三个原始缓存字段。
2. 持有本机修改锁和恢复点只读句柄；持久写入并回读验证 intent 及 seal，然后重新核对当前目标与值。
3. 同一唯一 radio 句柄立即 GET，核对地址、协议和预期测试名；只发送一次固定 UPDATE，再 GET 核对原名。
4. 退出进程，由独立观察程序核对磁盘、PnP 和驱动解析名；用户保持原通道及配对，正常关闭再开启键盘后再核对。

任何身份变化、外部名称、未知状态或请求失败均停止该位置写入。固定 intent 使用 CreateNew，阻止相同动作自动重放。预备的显式运行时回退只能恢复本次已知测试别名，且只接受成功清除的本轮证据；它是名称语义回退，原始 DIB 字节没有被转储。
